# Repo bearings

This repo doubles as the living home of the global pi agent config. Most
files here symlink into real config locations and apply machine-wide
immediately.

## Pi topology

install.sh is the source of truth for every symlink; verify with readlink,
never guess. Item-level links from .pi/ into ~/.pi/agent (never the whole
dir): settings.json, APPEND_SYSTEM.md (global system-prompt rules), mcp.json,
skills/, prompts/, themes/, extensions/. Never commit what lives only in
~/.pi/agent: auth.json, models.json, trust.json, sessions/, npm/, git/,
mcp-*cache.json.

Editing a .pi/ file here = global change, no install step. New files/dirs
need install.sh rerun.

## Extensions

.pi/extensions/ is real and tracked: package state (pi-permission-system,
config.json tracked) next to symlinks into
pi-extension-development/extensions/`<name>`/. Extensions are TS, loaded by pi
via jiti — no build step, edits live immediately. Verify with typecheck /
lint / format / test (hooks extension auto-runs the checklist on edits).
New extension = create dir + install.sh rerun.

.pi/extensions/cbmem.ts and .pi/skills/codebase-memory/ are generated by
`codebase-memory-mcp update` and gitignored.

## Other

- .pi-lens/config.json -> ~/.pi-lens/config.json (only tracked item there).
- dotfile symlinks: .tmux.conf, btop.conf, nvim/, ghostty/ (see install.sh).
- ~/.pi/agent/AGENTS.md holds the global codebase-memory-mcp rules; this
  file adds repo bearings only, don't duplicate.
